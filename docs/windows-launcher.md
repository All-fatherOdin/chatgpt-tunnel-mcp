# Независимый запуск туннеля на Windows

В корне репозитория запустите `Start-MCP-Tunnel.exe`. Он запускает скрытый фоновый процесс через локальную системную службу WMI (`Win32_Process.Create`), ожидает готовности и завершается. Окно лаунчера держать открытым не нужно. Процесс не является потомком Codex: закрытие запускающего терминала или Codex не должно завершать туннель.

Первый запуск запрашивает runtime API key скрытым вводом. Следующие запуски используют сохранённый DPAPI-ключ. Повторный запуск при работающем worker не создаёт дубль. Автозапуск при входе в Windows, расписание и автоматический рестарт после сбоя не устанавливаются. После перезагрузки компьютера запустите EXE снова.

## Управление

Запуск EXE также поднимает независимый скрытый диспетчер, если в
`config/dispatcher.local.json` задано `enabled: true`. Отсутствующая или
выключенная конфигурация оставляет режим только туннеля. Если туннель уже
работает, повторный запуск поднимает отсутствующий диспетчер без перезапуска
туннеля. Дубли защищены mutex и блокировкой журнала диспетчера.

`--status` показывает оба worker. `--stop` принудительно завершает оба
управляемых дерева процессов (включая исполнителя): не используйте его во
время задачи без необходимости; прерванный запуск может потребовать recovery.
Процессы, запущенные вручную отдельной командой, не останавливаются: перед
переходом на EXE завершите ручной диспетчер, когда он не выполняет задачу.
Логи диспетчера: `%LOCALAPPDATA%\chatgpt-tunnel-mcp\dispatcher-error.log`
и `dispatcher-output.log`; ошибки оболочки — `dispatcher-worker-error.txt`.
Логи перезаписываются при следующем запуске. Наличие процесса не гарантирует
успешного выполнения задачи: проверяйте журнал через dispatcher `--status`.
Автозагрузка Windows и автоматический рестарт после сбоя не добавляются.

Из PowerShell в корне репозитория:

```powershell
.\Start-MCP-Tunnel.exe
.\Start-MCP-Tunnel.exe --status
.\Start-MCP-Tunnel.exe --stop
```

`--status` показывает PID worker и проверяет `/readyz`. `--stop` завершает только найденное дерево worker текущего пользователя с точной командой этого репозитория, включая tunnel-client и MCP-процесс. Если на порту работает старый вручную запущенный туннель, остановите его в его терминале: лаунчер не завершает произвольного владельца порта.

Для смены ключа сначала выполните `--stop`, затем:

```powershell
.\Start-MCP-Tunnel.exe --reset-key
```

Локальная диагностика: http://127.0.0.1:8080/ui. При ошибке скрытого worker сообщение сохраняется в `%LOCALAPPDATA%\chatgpt-tunnel-mcp\worker-error.txt`; файл может относиться к предыдущему неудачному запуску. Текущую готовность проверяйте через `--status`. Ошибки сетевого соединения диагностируются также через локальный UI. Лаунчер не устраняет ошибки OpenAI или ограничения доступности сервиса.

## Хранение настроек

- `%LOCALAPPDATA%\chatgpt-tunnel-mcp\launcher.json` — путь к tunnel-client.exe.
- `%LOCALAPPDATA%\chatgpt-tunnel-mcp\runtime-key.dpapi` — ключ, зашифрованный для текущего пользователя Windows и устройства.
- `%APPDATA%\tunnel-client\chatgpt-tunnel-probe.yaml` — существующий профиль; лаунчер его не переписывает. Для этапа 3 он указывает planner.local.json.

Ключ не передаётся в аргументах WMI или процесса, не попадает в Git и постоянное окружение. Worker расшифровывает его локально и передаёт только дочернему tunnel-client через окружение. DPAPI не защищает от программ с правами того же пользователя. На другом устройстве ключ необходимо ввести заново.

## Сборка

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-launcher.ps1
.\Start-MCP-Tunnel.exe --check
```

EXE — оболочка над `scripts/start-tunnel.ps1`; держите его в корне репозитория. Бинарник исключён из Git, исходники сохранены; используется встроенный C#-компилятор .NET Framework. EXE не подписан. Для Windows PowerShell лаунчер устанавливает собственный PSModulePath, не наследуя несовместимые пути модулей PowerShell 7.

ExecutionPolicy Bypass применяется только к дочернему процессу. `--check` проверяет зависимости, профиль, сборку и доступность WMI-класса; не читает ключ и не запускает туннель. При отключённой WMI или запрете создания процессов запуск завершается ошибкой — зависимый от Codex резервный запуск не выполняется.

Сервер автоматически не пересобирается. После изменения сервера: `npm.cmd run build`, затем `--stop` и обычный запуск EXE. Внутренний параметр `-RunWorker` предназначен только для WMI; напрямую его запускать не нужно.

Основание механизма запуска: [Microsoft — Win32_Process.Create](https://learn.microsoft.com/en-us/windows/win32/cimwin32prov/create-method-in-class-win32-process).
