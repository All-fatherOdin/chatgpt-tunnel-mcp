# Проверка локального MCP из обычного ChatGPT

Дата: 2026-09-09.

## Результат

Пользователь подтвердил повторное чтение изменённого локального probe-файла через MCP в ChatGPT: после изменения файла изменились возвращаемые содержимое, SHA-256 и время чтения. Проверка проводилась по сценарию обычного чата без Work; отдельной записи интерфейса режима и сырых результатов вызовов в репозитории нет.

Техническая гипотеза доступа ChatGPT к актуальным локальным данным подтверждена по результатам ручной проверки пользователя. Источник расходования лимитов не установлен.

## Проверенная последовательность

1. Создан Secure MCP Tunnel и runtime API key.
2. Установлен основной клиент tunnel-client v0.0.14 для Windows amd64.
3. Создан stdio-профиль chatgpt-tunnel-probe для локального TypeScript MCP-сервера.
4. Выполнен doctor: RESULT ok. Проверки сети для stdio и необязательного Codex-плагина отмечены SKIP, что не препятствовало продолжению.
5. Запущен клиент туннеля.
6. В ChatGPT включён Developer mode и создан плагин chatgpt-tunnel-probe: подключение Tunnel, аутентификация No Authentication на уровне тестового MCP. Runtime key используется клиентом туннеля отдельно.
7. После обновления страницы установленный плагин появился в меню чата.
8. Пользователь выполнил чтение, изменил локальный probe-файл и повторил вызов. Пользователь сообщил: «я проверил в чате, все строки изменились».

## Практические замечания

- В Windows PowerShell политика выполнения может блокировать npm.ps1. Использовать npm.cmd run build без изменения политики.
- Нужен архив tunnel-client-v0.0.14-windows-amd64.zip. Архив runtime-cloudflared содержит вспомогательный компонент, а не основной клиент.
- Использовать фактический путь к распакованному tunnel-client.exe.
- Сначала init, затем doctor и run: doctor не создаёт отсутствующий профиль.
- В значении --mcp-command использовать пути с прямыми слешами C:/...: при разборе команды клиент удалял обратные слеши, и preflight не находил скрипт.
- Ключ вводить в отдельное приглашение Read-Host -AsSecureString, не подставлять в текст команды или приглашения. Секреты не сохранять в документации и Git.
- Оставлять tunnel-client run запущенным во время discovery и вызовов.
- Если установленный плагин не виден в меню, обновить страницу ChatGPT.
- Для изменения probe-файла открыть другое окно PowerShell. При абсолютном пути смена каталога не требуется.

## Границы доказательств

- Итог чтения подтверждён пользователем; точные значения контрольных строк и хешей не сохранены.
- Независимый вызов из Codex в этом эксперименте не зафиксирован.
- Учёт лимитов ChatGPT/Work/Codex не проверен.
- Чтение произвольных проектов, запись, передача заданий и автоматический запуск исполнителя не проверялись.
