## Обнаруженные ограничения и ошибки процедуры

1. В исходной инструкции был предложен не-UUID idempotencyKey. Строгая схема отклонила запрос INVALID_INPUT; после замены на UUID создание прошло. Ошибка не называла неверное поле. Улучшение диагностик остаётся отдельной задачей.
2. Planner в ChatGPT намеренно не имеет claim_task/submit_report. Эти вызовы выполняются в Codex через worker; первоначальная инструкция сопровождения перепутала клиент.
3. При переключении профиля пользовательский туннель был заменён фоновым процессом, запущенным из Codex. После закрытия Codex наблюдались отсутствие tunnel-client и HTTP 504/Session terminated. Повторный запуск восстанавливал readyz и работу без потери данных. Независимость запуска EXE из Проводника от закрытия Codex в этой приёмке отдельно не проверялась. Для постоянной работы нужен независимый запуск туннеля; автоматическое восстановление не реализовано.
4. Ручная ветка проверена с blocked; failed/cancelled и конкурентные переходы покрывались автоматическими тестами. Учёт лимитов подписки не проверялся. Приёмка функциональная, не доказательство непрерывной доступности туннеля.
