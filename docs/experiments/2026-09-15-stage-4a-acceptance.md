### Протокол проверки ротации

Для короткого теста временно установить `maxSessionTasks: 2` у тестируемого
проекта и перезапустить диспетчер в отсутствие активных задач. Записать
исходное значение и восстановить его после теста. Изменение затрагивает
все новые запуски этого проекта, поэтому не смешивать тест с другими задачами.

Создать отдельную цепочку из трёх маленьких задач на один новый тестовый файл:
первая с `session.mode: new`, вторая и третья с `auto` и `parentTaskId`
непосредственного предшественника. После первых двух отчётов оформить
запланированный `changes_requested`. Для каждого следующего шага обновлять
sourceRefs. Не менять ветку/HEAD и не запускать посторонние задачи в этой
сессии. Сохранить ограничения: только тестовый файл, без commit/push.

Ожидание: первый шаг — `new`; второй — `resume` с тем же threadId;
третий — `new`, другой threadId и причина `session_task_limit_handoff`.
Третья задача должна получить контекст предшественника и корректно выполнить
доработку. Иная причина новой сессии не подтверждает ротацию именно по лимиту.
Зафиксировать ID, executionStatus и проверку результата; затем вернуть лимит
и перезапустить диспетчер после завершения задач. Ранее принятые задачи
не переоткрывать и не менять для подготовки теста.
