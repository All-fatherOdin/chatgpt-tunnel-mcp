# Постраничное чтение: project-read/2

`read_file`, `list_files` и `search_text` возвращают ограниченные страницы с
`read_contract: "project-read/2"`, `trust: "UNTRUSTED_EVIDENCE"`, `source_id`,
`generation`, `coverage` и `continuation`. Tunnel переносит сообщения; пагинацию
выполняет локальный сервер. Общего лимита числа страниц нет.

## Правило продолжения

Если `continuation` не `null`, следующий вызов берётся **дословно** из:

```json
{
  "next_tool": "read_file",
  "next_arguments": {
    "projectId": "example",
    "path": "logs/run.txt",
    "startLine": 1,
    "endLine": 100000,
    "cursor": "<opaque signed token>"
  }
}
```

Имена и аргументы в этом примере иллюстративны. Исполнять нужно продолжение из
реального ответа. Не вычислять новый `startLine` и не декодировать cursor.
`continuation.cursor` дублирует cursor в `next_arguments` для хранения.

Cursor содержит версию, digest области запроса, поколение источника и позицию;
HMAC защищает от изменения позиции и счётчиков. Область включает инструмент,
корень/политику проекта, путь, диапазон либо поисковый запрос. Для списка и поиска
`limit` можно уменьшать/увеличивать в пределах конфига без смены области; обычный
агент всё равно должен исполнять готовое продолжение. Старые offset-only cursors
не поддерживаются. Изменение пути, диапазона, запроса или snippetChars требует
нового чтения.

`source_id` детерминирован из projectId и относительного пути. Он обозначает
логический источник; `generation` отличает его версии. Идентичность списка и
поиска относится к каталогу в заданной области, а не к отдельному совпадению.
Каждый поисковый результат дополнительно содержит `source_id` своего файла.

## Чтение файлов

Логический диапазон может быть больше одной страницы. Физическая страница
ограничена 750 строками/фрагментами и полным бюджетом ответа. Файл должен быть
валидным UTF-8 без NUL; UTF-8 BOM учитывается в SHA, но не входит в текст.
`endLine` за EOF по-прежнему является `INVALID_RANGE`.

Длинная строка передаётся несколькими фрагментами:

```text
lines[].line          номер логической строки, начиная с 1
lines[].text          текст фрагмента
lines[].startByte     включительная позиция в исходном файле
lines[].endByte       исключительная позиция, включая терминатор строки при наличии
lines[].lineComplete  дошли ли до конца этой строки
byteRange             физический диапазон всей страницы
requestedRange        исходный логический диапазон
range                 диапазон строк страницы и totalLines файла
```

Для сборки текста объединять фрагменты с одинаковым `line` без добавления
перевода строки. Между завершёнными логическими строками добавлять перевод
строки по нужному формату. `content` — удобное представление **текущей страницы**:
оно соединяет её фрагменты через LF, нормализует CRLF и не сохраняет последний
терминатор. Простое соединение `content` разных страниц через LF ошибочно для
разделённой строки. Это API текста, а не экспорт исходных байтов файла.

`truncated=true` означает, что остаются байты **запрошенного диапазона**;
`nextStartLine` сохранён как навигационная подсказка, но не заменяет cursor.
При разделённой строке он указывает ту же строку. Никогда не считать строку
прочитанной целиком по одному её номеру.

`sha256` покрывает все исходные байты файла. На первом обращении сервер потоково
проверяет UTF-8, вычисляет SHA-256 и строит разреженный индекс (опорная позиция
через 750 строк). Кэш содержит только метаданные/индекс, не содержимое файлов;
ограничен 32 файлами и 250 000 опорными позициями суммарно. При вытеснении индекс
строится заново. Следующие страницы используют byte offset и чтение диапазона.
Операционная память не растёт пропорционально длине отдельной строки.

Поколение файла включает dev/inode, размер, mtime и ctime с наносекундными полями
Node. Проверяются путь и открытый дескриптор до/после чтения. SHA кэшируется при
неизменном поколении; сервер не перечитывает весь файл ради нового SHA на каждой
странице. Это обнаружение обычных изменений/замен, **не неизменяемый снимок ФС**
и не защита от привилегированного изменения данных с подделкой метаданных.
Дописывание live-лога также меняет поколение: страницы разных поколений нельзя
смешивать. Для постоянно меняющихся логов читать стабильную копию/закрытый лог.

## Поиск и покрытие

`search_text` сохраняет literal, case-sensitive поиск: не более одного результата
на совпавшую строку. Запрос не сопоставляется через границу строк. Ограничение
количества результатов, размера ответа или времени выдаёт продолжение, включая
случай остановки внутри длинной строки. Cursor хранит ограниченный хвост для
поиска совпадения через границу блока и начало найденного snippet.

Перед выдачей совпадений файл полностью проверяется на UTF-8/NUL; недопустимый
хвост не может позднее обесценить уже возвращённые совпадения. Список файлов и
их поколения проверяются для каждой страницы и повторно перед её возвратом.
Добавление/удаление файла или изменение его поколения делает цепочку устаревшей.

`coverage` для поиска и списка содержит:

- `status`: `complete`, `partial` или `none`;
- `requested_targets`, `processed_targets`, `pending_targets`;
- `skipped_target_count`, `skipped_reason_counts`;
- до пяти примеров `skipped_targets`;
- `skipped_targets_digest_sha256`: накопительная SHA-256 цепочка пропусков
  в порядке обхода, начиная с SHA-256 сериализованного пустого массива.

Счётчики накопительные по цепочке, а `results`/`entries` относятся только к
текущей странице. У поиска обработанным считается **полностью проверенный и
просканированный** файл. `progress.next_path/next_line/next_byte` показывает
следующую позицию; продолжать всё равно нужно по opaque cursor. Ошибки доступа,
размера, кодировки, ссылочные и неперечислимые цели отражаются как пропуски.

Покрытие относится к разрешённой политикой области. Исключённые `.env`, секреты,
служебные каталоги и запрещённые расширения не перечисляются и не считаются
пропущенными. `list_files` покрывает только заявленную `depth`. При недоступном
подкаталоге известен пропуск его корня, но число скрытых потомков неизвестно:
счётчик целей не является полным инвентарём такого дерева. Для списка отдельно
учитываются возвращённые записи и неудавшиеся обходы поддеревьев.

Защитные пределы обхода: 100 000 обнаруженных записей/пропусков; для поиска
100 уровней вложенности с явным `DEPTH_LIMIT` при более глубоком дереве. При
слишком большом каталоге требуется сузить `path`. `searchTimeoutMs` — мягкий
бюджет сканирования страницы между операциями I/O: построение/проверка каталога
и первоначальная валидация большого файла не имеют жёсткого wall-clock deadline.
Если до дедлайна не сделано никакого продвижения, возвращается `SEARCH_TIMEOUT`,
а не бесконечная цепочка одинаковых продолжений.

Финальный `continuation=null` не равен полному покрытию: при пропусках
`coverage.status` останется `partial`/`none`, `limited=true`. Пустой результат
такого поиска не доказывает отсутствие совпадений. Для `read_file` покрытие
содержит запрошенное и накопительное число завершённых строк, отдельно число
завершённых строк текущей страницы. `complete` относится к requestedRange.

## Размеры и конфигурация

`maxResponseBytes` теперь означает бюджет **сериализованного ответа**, включая
оба представления MCP, JSON escaping и оболочку JSON-RPC. При подборе страницы
резервируется 256 байт для оболочки; stdio transport дополнительно проверяет
реальное сообщение с реальным request ID и завершающим LF. Слишком большой
ответ заменяется ошибкой `RESPONSE_PAGE_TOO_LARGE`. Если даже ошибка с request ID
не помещается, соединение закрывается. Для всех исходящих stdio сообщений
действует дополнительный потолок 8 000 000 байт. Это установленный предел нашего
сервера, а не заявление о лимите внешнего Tunnel/ChatGPT.

Лимит файла по умолчанию сохранён: 1 МиБ. Для больших логов можно явно увеличить
`maxFileBytes` до 1 ГиБ. Он остаётся ограничением допуска файла, а не страницы.
По умолчанию ответ — 128 КиБ, допустимый диапазон — 4096..1048576 байт. Старые
конфиги с меньшим бюджетом теперь отклоняются при запуске: в них не помещается
надёжный контракт продолжения. Минимум 4096 не гарантирует, что произвольные
длинные пути, snippets и metadata поместятся; тогда нужно уменьшить scope/snippet
или увеличить бюджет. Просто уменьшение количества строк не всегда помогает.

## Ошибки и восстановление

Ошибки проектного чтения содержат `code`, `message`, `correlationId`,
`retryable=false`, `do_not_retry_same_arguments=true` и `recovery`.
Для `CURSOR_STALE`, `CURSOR_INVALID`, `SOURCE_CHANGED_DURING_READ` recovery даёт
точные `next_tool`/`next_arguments` исходного запроса без cursor, максимум одну
попытку. Перед ней отбросить накопленные результаты старой цепочки. Остальные
ошибки требуют исправления запроса/настройки или явного сообщения о неполноте;
не повторять неизменный вызов. Ошибка транспортного бюджета может приходить как
JSON-RPC error, а не `isError`-результат инструмента.

Чтобы пережить compaction, агент сохраняет **после обработки страницы** во
внешних заметках задачи: исходный запрос, `source_id`, `generation`, SHA при
наличии, последнюю подтверждённую позицию, точный `continuation` и накопленные
выводы/coverage. Восстановив заметки, выполняет continuation, а не угадывает
смещение. Сервер возвращает необходимые anchors, но не создаёт и не обновляет
заметки агента самостоятельно. Это обязанность вызывающего workflow.

Подпись cursor действует в одном процессе MCP. Compaction разговора её не
меняет, перезапуск сервера — меняет. После перезапуска старый cursor получает
`CURSOR_INVALID` с готовым запросом для нового чтения. Кэш можно вытеснить без
потери валидности cursor, если процесс и источник не изменились.

При остановке по бюджету агента явно сообщить непрочитанную область и сохранить
продолжение. Протокол делает неполноту наблюдаемой, но не гарантирует послушание
модели или сохранение всех страниц в её контексте. Предпочтительный порядок:
поиск → релевантные диапазоны → вывод с указанием фактического покрытия.

## Проверка

`test/read-protocol.test.ts` проверяет сборку UTF-8/CRLF и длинных строк,
границы диапазонов, SHA, повторное использование индекса, файлы больше прежнего
предела 4 МиБ, scope/generation/tamper проверки, полноту поиска, ограниченные
пропуски, продолжение по времени и реальные сериализованные transport frames.
`test/mcp.test.ts` проверяет те же вызовы через MCP/stdio, исполнимый recovery
и инвалидирование cursor после перезапуска. Живой внешний Tunnel этими тестами
не проверяется.
